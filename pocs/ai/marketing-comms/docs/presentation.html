01 — Problem

Four manual steps

One of them is not like the others

A sales rep needs a two-column brief about a partnership between their company and a prospect. Today:

  • Read both companies' material
  • Pull out the claims worth making
  • Write the copy
  • Fight the copy into a fixed page layout until it fits

Three of those are judgement.
The fourth is arithmetic.

The obvious move is to hand all four to a model. That is where this goes wrong — and the failure is instructive rather than embarrassing.
02 — The reframe

Layout fitting is constraint satisfaction

Not generation. This is the whole argument.

Ask a model for "a headline that fits a nine-word slot" and you will get eleven words often enough to matter. That is not a prompting problem, and "remember, at most nine words" does not fix it reliably.

A language model cannot count its own tokens before emitting them. Asking it to try spends capability on a task that len(text.split()) settles exactly.

Counting characters is a job for code.
The model's job is content.

The model proposes. Deterministic code disposes. Everything else in this design follows from taking that seriously.

Standing assumption: "fits the layout" means word and character counts, not rendered typography. If the real constraint is pixels after font metrics, the validator's structure survives — a max_rendered_px constraint kind is one new enum arm — but every number in the template would be wrong.
03 — Architecture

One diagram

A fixed linear pipeline with one bounded loop

POST /collateral
      │
      ▼
  ┌──────────────────────────────────────────────┐
  │ 202 Accepted + job_id       (returns ~instantly) │
  └──────────────────────────────────────────────┘
      │  background task
      ▼
  ingest ──▶ extract ──▶ ground ──▶ draft ──▶ validate ──┐
  (PDF)      (facts)     (verify)   (LLM)    (pure fn)   │
                                       ▲                 │
                                       │  violations     │
                                       └──── repair ◀────┤ invalid,
                                            (≤3×)        │ budget left
                                                         │
                                     fallback ◀──────────┤ invalid,
                                    (truncate)           │ budget spent
                                                         │
                                      stored JSON ◀──────┘ valid

Generation is up to four sequential model calls, which is past what a client should hold a connection open for — hence 202 + poll.

But the async shape is not only about latency. A synchronous endpoint would push back against retrying, and the retries are where the guarantee comes from. Async is what makes the repair loop affordable.

No retrieve stage. See slide 9.
04 — The centrepiece

The layout contract

Validator, repair loop, fallback

Limits carried three ways

  • JSON Schema — documentation. The SDK strips maxLength before the call; word counts have no schema equivalent at all.
  • Prompt prose — where the model can act on the numbers.
  • The validator — pure function. This one decides.

The schema still earns its place: additionalProperties: false and required are enforced, removing two whole violation classes before the first call.

Repair, bounded at 3

Violations carry hints computed in code: "Shorten 'headline' from 14 to at most 9 words."

The whole draft goes back, not just the bad fields — shortening one column changes how it balances against the other, and isolated edits read as though assembled from parts.

Fallback cannot fail

Budget spent? Deterministic truncation, padding, and synthesis. Every violation kind has a mechanical repair.

Poll to a terminal state and you get a contract-valid draft or an explicit failure. Never an invalid draft.

Padding filler is deliberately meaningless ("and"). The alternative — inventing content to reach a word floor — is a grounding violation dressed up as a repair.
05 — Ingest

Hybrid, and why grounding needs the text path

Text path — pymupdf

Extracts text and records, per fact, the page and character span it came from. Cheap, and verifiable.

Vision path — gated

Only for pages under MIN_PAGE_TEXT_CHARS = 200 — scans and image-heavy slides. Facts carry VISION_CONFIDENCE = 0.7 and no span.

The gate is a cost decision as much as a quality one: vision bills per page, and running it over pages that already gave clean text buys nothing.

Grounding is a block, not a warning

verify_facts drops any fact whose span does not resolve in the source. A fact that cannot be traced never reaches the prompt.

So a hallucinated citation cannot survive into the draft by being merely low-confidence — the span either resolves or the fact is gone.

That is why the text path is not just the cheap path. It is the only path that produces something checkable.

Sender and receiver facts are kept apart end to end — fetched by company and role, rendered under separate headings. Collateral about a partnership attributes claims to one party or the other, and a flat list invites the model to mix them.
06 — Demo

Upload → poll → valid JSON

# 1. upload context, tagged by role
curl -X POST localhost:8000/companies/meridian/context \
     -F "file=@sender.pdf" -F "role=sender"
# → 201 {"pdf_id": "...", "company_id": "meridian", "role": "sender"}

# 2. request collateral — returns immediately
curl -X POST localhost:8000/collateral \
     -H "content-type: application/json" \
     -d '{"sender_company_id": "meridian",
          "receiver_company_id": "calder",
          "prompt": "Announce the partnership."}'
# → 202 {"job_id": "...", "status": "queued"}

# 3. poll
curl localhost:8000/jobs/$JOB_ID
# → 200 {"status": "succeeded",
#        "draft": { ...nine fields, every one inside its limits... },
#        "used_fallback": false, "repair_attempts": 0, "fact_count": 14}
If the live demo misbehaves, that is still a demo: the fallback path means even a bad generation returns contract-valid JSON with used_fallback: true. A degraded demo is a working demo.
07 — Numbers

Four metrics

12 cases, easy through hard

MetricValueMeaning
Contract pass rate58.3%valid on first generation

Grounding rate91.7%traceable to a source span

Read the first row and the last row together. First-pass compliance is a coin flip — which is exactly the argument for not trusting the model with arithmetic. The 100% is not the model getting better; it is the deterministic layer doing its job.

Said out loud: these come from scripted fixtures and synthesized PDFs, not the client's real documents. The harness replays fixed responses, so the pass rate measures the harness, not a live model. It is a working instrument, not a benchmark — and running it against a live model is the first thing I would do next.
08 — Cloud

Five components

Design target — not what runs today

Cloud Storage ─▶ Pub/Sub ─▶ Cloud Run ─▶ Vertex AI ─▶ Firestore
   (PDFs)        (jobs)     (API+worker)   (model)     (jobs+docs)
                    │
                    └─▶ jobs-dlq  (3 attempts, then alert)

Idempotency

Dedup key sha256(sender, receiver, template, prompt), enforced as a conditional write on the job document. Delivery is at-least-once — without it, a redelivered message is a second billed generation.

Two retry layers, not one

Queue retries are for infrastructure failure. The repair loop is for contract failure — and is not a retry at all, but a new prompt carrying computed violations.

AWS maps cleanly

S3 → SQS/EventBridge → Lambda → Bedrock → DynamoDB.

Three real differences: Lambda's 15-minute ceiling, SQS FIFO's 5-minute dedup window being too short (so the datastore is the real guarantee, on both clouds), and Bedrock structured-output enforcement — the one item worth checking against current docs, since it is load-bearing.

What actually runs today: one FastAPI process, SQLite, in-process background tasks. The storage layer is document-shaped and the model sits behind a port, so this is a driver swap — but it is a plan, not a deployment.
09 — Restraint

What we did not build

Each considered, each declined, each with a reason

  • ✕No orchestration framework (LangGraph et al.) — a fixed linear DAG with one bounded loop is an async def with a while. A graph framework adds an execution model and a debugging surface to express control flow Python already expresses in ten lines.
  • ✕No vector store / RAG — retrieval solves too much context. A company's context here is a handful of PDFs that fit in a prompt whole. Chunking would add an index to maintain, a threshold to tune, and a new failure mode — the relevant fact ranks 4th and gets cut — for nothing.
  • ✕No MCP — MCP standardizes exposing tools to a model. This pipeline gives the model no tools. One interaction: "return JSON matching this schema." A protocol for tool exposure has nothing to attach to.
  • ✕No Kubernetes — a stateless HTTP service with background work. Cloud Run and Lambda both run that with no cluster to operate.

Each is declined against this problem at this scale — not in general. The RAG call flips the moment context outgrows a prompt.

10 — Next

The honest gaps

  1. Run the evals against a live model. Every number on slide 7 comes from a scripted provider. Real first-pass compliance is the single most informative missing measurement — and it is a day's work.
  2. A real job queue. BackgroundTasks dies with the process: an in-flight job is lost on deploy, with no retry. The cloud design solves this; the prototype does not. A genuine gap, not a simplification.
  3. Idempotency locally. The dedup key is specified in the cloud design and not implemented here. Resubmit an identical request today and it generates — and bills — twice.
  4. Per-field repair targeting. An over-long headline currently resends all nine fields. Right for coupled fields (the two columns), wasteful for independent ones.
  5. More templates. One template proves the mechanism and does not prove it generalizes. A single-column and a social-card layout would test whether these constraint kinds are the right vocabulary.
And the assumption worth surfacing again: if "fits the layout" means rendered pixels rather than word counts, the architecture holds but every constraint value in the template is wrong. That is the first question I would want answered.
